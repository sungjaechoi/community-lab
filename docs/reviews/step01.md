최초 검토 당시 아래 기본안은 아직 사용자 확인을 받지 않은 제안이었다. 현재는 사용자가 P-01~P-08을 초안대로 확인했으며 제품 내용은 변경하지 않았다. 아래 표와 최초 미정 사항은 당시 맥락으로 보존한다.

## 3. 사용자가 검토하는 방법과 기대 결과

문서를 열어 아래 흐름을 읽으며 기대하는 서비스와 맞는지 확인한다. 지금 앱을 실행하거나 외부 계정에 로그인할 필요는 없다.

| 순서·행동 | 문서에서 확인할 기대 결과 |
| --- | --- |
| 1. 비로그인으로 글을 읽고 글쓰기를 선택한다고 가정 | 공개 조회 가능, 작성은 로그인 후 작성 폼 복귀. S-02→S-01→S-04 |
| 2. A의 글에 B가 답글을 쓰고 A가 부모 댓글을 삭제한다고 가정 | 삭제 부모의 원문은 보이지 않고 답글 유지, 새 답글 금지. 댓글 정책·AC-COMMENT-01~04 |
| 3. A가 B에게 친구 요청, B 수락 뒤 쪽지·채팅 시작 | 글 작성자 버튼→받은 요청→친구 목록→쪽지/방. 사용자 검색 없이 진입 가능 |
| 4. 친구 삭제 후 과거 쪽지·방을 연다고 가정 | 기록은 조회 가능, 새 발송 거부. 재친구는 새 요청·수락, 기존 방 재사용 |
| 5. C가 A·B 쪽지·방 ID를 안다고 가정 | 서버 직접 요청·Realtime 구독에서 거부. 화면에서 숨기는 것만으로 완료하지 않음 |
| 6. 빈 입력·저장 실패·같은 전송 재시도를 가정 | 필드 오류·입력 보존·실패 상태. 채팅은 한 번 저장/한 줄 표시, 친구 수락은 전체 성공 또는 롤백 |

확인할 것은 제품 범위와 정책의 적합성이다. API와 UI가 실제 동작하는지는 각 기능 구현 뒤 별도 REVIEW에서 확인한다. 면접 질문은 학습 자료이며 답변 시험을 통과해야 승인되는 절차는 아니다.

## 4. 실제 점검 결과와 한계

- 적용 지침: 시작 폴더 `AGENTS.md`. 기존 플랜 범위·STEP 01과 관련 STEP 04·05·09·10·11을 읽어 초안과 대조했다.
- 폴더 조사: 시작 시 `AGENTS.md`, `START-HERE.md`, `community-lab-work-plan.md`, 루트 `work-status.md`와 `.DS_Store`가 있었다. 앱 코드·package.json·docs 폴더·기존 완료 이력은 없었다.
- Git 조사: `git status --short --branch`는 저장소가 아니라는 결과(exit 128)를 반환했다. STEP 01 규칙에 따라 저장소를 만들거나 커밋하지 않았다. 브랜치·remote·staged는 적용 대상이 없다.
- 기록 경로 정정: 루트의 초기 기록을 읽고 `docs/work-status.md`에 필드를 이어서 작성했다. 루트 `work-status.md`는 정식 기록을 가리키는 안내로 남겼다. 보존할 과거 승인·구현·커밋 이력은 없었다.
- 문서 점검: 요구사항·화면·수용 기준의 ID 연결, 상대 링크, STEP 01 체크박스·대기 상태를 실제 파일로 확인했다. 최종 수치와 결과는 아래 점검 기록에 남겼다.
- 기술 선택은 플랜과 공식 1차 문서를 대조했다. 기술 문서 안에 근거 링크를 붙였다. 공식 문서 조회를 실제 서비스 연결 성공으로 취급하지 않는다.
- 미검증: 타입·린트·빌드·테스트·API·DB·Google OAuth·Realtime·실제 반응형/접근성·성능. 앱과 실행 설정이 없어 이번 문서 단계에서 실행하지 않았다.
