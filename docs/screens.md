# STEP 01 화면 명세

상태: `01-REVIEW DONE / 01-RECORD DONE` · 작성일: 2026-10-26 (Asia/Seoul). 사용자가 P-01~P-08을 초안대로 확인했다. 최초 검토 이력·실제 응답·기록 시각은 [확인 기록](reviews/step01.md)에 보존했다.

이 문서는 `01-02`, `01-07`, `01-08`의 화면 검토 자료다. URL은 앱을 만들 때 사용할 경로의 제안이며 현재 접속 가능한 주소가 아니다. 실제 화면·API 연결·모바일 검증은 아직 수행하지 않았다. 요구사항과 API·검증의 연결은 [requirements.md](requirements.md), 허용 행동의 기준은 [authorization.md](authorization.md)를 함께 본다.

## 1. 화면을 먼저 정하는 목적과 WHY

사용자가 어디서 기능을 시작하고 성공·실패 뒤 무엇을 보게 되는지 정한다. 예를 들어 친구 요청 API만 있어도 상대를 고를 화면이 없다면 사용자는 요청을 보낼 수 없다. 이번에는 게시글 작성자 옆에서 친구 요청을 시작하고 친구 목록에서 쪽지·채팅으로 이어지는 흐름을 기본안으로 제안한다. 별도 사용자 검색을 추가하지 않아도 필수 기능을 사용할 수 있기 때문이다.

플랜에 정해진 필수 화면과 대댓글 깊이 1단계는 유지한다. 공개 범위·친구 삭제 후 동작·시각 방향은 P-01~P-08 승인 기준을 따른다. URL·배치는 구현을 위한 초안이며 실제 화면의 결과는 후속 UI REVIEW에서 확인한다.

## 2. 메뉴와 기본 이동

| 대상 | 메뉴·진입점 | 기대 이동 |
| --- | --- | --- |
| 공통 | 로고·게시글 | `/`는 `/posts`로 이동하고 게시글 목록 표시 |
| 비로그인 | 로그인, 글 작성·댓글 작성 안내 | `/login`으로 이동. 로그인 성공 뒤 허용된 원래 앱 화면으로 복귀 |
| 로그인 | 게시글 · 친구 · 쪽지 · 채팅, 사용자 표시·로그아웃 | 현재 메뉴 위치 표시. 쪽지는 수신함, 채팅은 방 목록으로 이동 |
| 게시글 상세 | 작성자 옆 친구 요청 | 자신에게는 숨기고, 상대와의 요청 대기·친구 상태에 맞는 행동 표시 |
| 친구 목록 | 친구 행의 쪽지·대화 시작 | 수신자가 선택된 작성 폼, 새 방 또는 기존 1대1 방으로 이동 |
| 빈 채팅 목록 | 친구에게 대화 시작 | 친구 목록으로 이동하여 실제 대상을 선택 |

로그인 복귀 경로는 앱 내부의 허용 경로만 사용한다. 외부 주소로 임의 이동시키지 않는다. 로그아웃 후 개인 화면·개인 데이터 표시와 채팅 구독을 정리하고 공개 게시글 목록으로 이동하는 안이다.

## 3. 화면 목록과 시작 → 결과

`[postId]`, `[messageId]`, `[conversationId]`는 실제 데이터 ID가 들어갈 자리다. `recipientId`는 친구 목록에서 선택한 공개 사용자 ID이며, 서버에서 현재 발송 가능 관계를 다시 검사한다.

| 화면 ID · 요구사항 | URL 초안 | 사용자·주요 구성 | 시작 → 성공 뒤 결과 |
| --- | --- | --- | --- |
| S-01 · R-AUTH-01 | `/login` | 비로그인, Google 로그인 버튼·실패 안내 | 보호된 행동 또는 로그인 메뉴 → 인증 → 원래 허용 화면, 복귀 경로가 없으면 `/posts` |
| S-02 · R-POST-01 | `/posts` | 누구나 공개 글 조회, 제목·작성자·작성 시각·글쓰기·더 보기 | 메뉴 진입 → 글 선택 → S-03. 글쓰기 선택은 로그인 후 S-04 |
| S-03 · R-POST-01, R-COMMENT-01, R-FRIEND-01 | `/posts/[postId]` | 공개 글·작성자·댓글/답글, 작성자 수정·삭제, 친구 요청 진입 | 글 선택 → 읽기·댓글 작성. 작성자 수정은 S-05, 글 삭제 성공은 S-02 |
| S-04 · R-POST-01 | `/posts/new` | 로그인, 제목·본문·취소·등록 | 글쓰기 → 입력·등록 → 새 글의 S-03 |
| S-05 · R-POST-01 | `/posts/[postId]/edit` | 해당 글 작성자, 기존 제목·본문·취소·저장 | S-03 수정 → 기존 값 편집·저장 → 같은 글의 S-03 |
| S-06 · R-FRIEND-01 | `/friends` | 로그인, 친구·받은 요청·보낸 요청 탭, 수락·거절·친구 삭제 | 글 작성자에게 요청 → 보낸 요청 표시. 수신자 수락 → 양쪽 친구 목록 갱신. 친구 행에서 S-10/S-12로 진입 |
| S-07 · R-INBOX-01 | `/inbox` | 로그인, 자신의 수신함·읽음 표시·발신함 이동·쪽지 쓰기 | 쪽지 메뉴 → 수신 쪽지 선택 → S-09. 쓰기는 친구 목록에서 대상 선택 |
| S-08 · R-INBOX-01 | `/inbox/sent` | 로그인, 자신의 발신함·수신함 이동 | 발신함 → 보낸 쪽지 선택 → S-09 |
| S-09 · R-INBOX-01 | `/inbox/[messageId]` | 해당 쪽지 발신자·수신자, 상대·본문·시간·내 쪽지 삭제 | 받은 쪽지 상세 열기 → 수신자의 읽음 반영. 삭제 성공 → 진입했던 자신의 수신함/발신함 |
| S-10 · R-INBOX-01 | `/inbox/new?recipientId=...` | 로그인, 선택된 친구·본문·발송·취소 | S-06에서 친구 선택 → 발송 → 보낸 쪽지의 S-09, 발신함은 S-08. 직접 진입해 대상이 없으면 친구 목록 선택 안내 |
| S-11 · R-CHAT-01 | `/chats` | 로그인, 자신이 참여하는 방·상대·최근 메시지·친구 목록 진입 | 채팅 메뉴 → 기존 방 선택 → S-12. 새 대화는 S-06에서 대상 선택 |
| S-12 · R-CHAT-01 | `/chats/[conversationId]` | 방 참여자, 상대·메시지 이력·이전 메시지·작성창·연결 상태 | 친구 행의 대화 시작 또는 S-11 → 같은 사용자 쌍의 방 열기 → 저장 결과와 수신 메시지 표시 |

R-UI-01은 S-01~S-12 전체에 적용한다. 별도의 탈퇴 화면, 프로필 편집, 검색, 파일·이미지 첨부, 친구 요청 취소 화면은 이번 MVP(필수 흐름을 갖춘 첫 범위)에서 보류한다. 쪽지 답장은 새 작성 화면을 사용하고 현재 친구일 때만 발송한다. 독립된 답장 기능이나 단체 채팅은 추가하지 않는다.

쪽지 상세에 직접 접근했거나 발송 직후라서 돌아갈 함 정보가 없으면, 삭제 성공 뒤 발신자는 발신함(S-08), 수신자는 수신함(S-07)으로 이동한다.

## 4. 화면별 로딩·빈 결과·실패·권한 상태

| 화면 | 로딩·처리 중 | 빈 결과 | 실패·재시도 | 권한·관계 변화 |
| --- | --- | --- | --- | --- |
| S-01 | 인증 시작 표시, 반복 클릭 방지 | 로그인 전 안내 | 인증 취소·실패 문구와 다시 로그인 | 이미 로그인했다면 허용된 복귀 화면으로 이동 |
| S-02 | 첫 목록과 더 보기 로딩 구분 | “아직 게시글이 없어요”와 글쓰기 | 조회 실패 영역에 재시도, 기존 조회 글 유지 | 비로그인은 읽기 가능, 글쓰기는 로그인 안내 |
| S-03 | 글·댓글 로딩 구분 | 댓글 없음과 첫 댓글 안내 | 글 오류·댓글 오류를 구분. 댓글만 실패하면 글은 유지 | 비로그인 작성 안내. 타인의 수정·삭제 숨김. 삭제되거나 없는 글은 찾을 수 없음 |
| S-04 | 등록 중 표시, 중복 클릭 방지 | 빈 폼과 입력 기준 | 필드 오류·저장 오류, 제목·본문 보존 | 세션 만료 시 재로그인 안내, 자동 재제출하지 않음 |
| S-05 | 기존 값 조회·저장 중 표시 | 없는 글은 폼을 비우지 않고 찾을 수 없음 | 조회·저장 오류 구분, 수정 내용 보존 | 타인 직접 URL 접근 거부. 편집 중 삭제된 글은 저장 실패 안내 |
| S-06 | 탭 조회·행별 처리 중 표시 | 친구 없음/받은 요청 없음/보낸 요청 없음 각각 표시 | 해당 탭·행에서 재시도, 실패한 친구 행을 임의 제거하지 않음 | 수신자만 수락·거절. 다른 창에서 처리됐다면 충돌 안내 후 목록 갱신 |
| S-07 | 수신함 조회·추가 로딩 | 받은 쪽지 없음, 친구에게 쪽지 쓰기 진입 | 조회 재시도, 기존 목록 유지 | 로그인 필요, 자신의 수신함만 표시 |
| S-08 | 발신함 조회·추가 로딩 | 보낸 쪽지 없음, 친구 선택 진입 | 조회 재시도, 기존 목록 유지 | 로그인 필요, 자신의 발신함만 표시 |
| S-09 | 상세·읽음 반영·삭제 중 표시 | 없거나 내 함에서 삭제한 쪽지는 찾을 수 없음 | 조회·읽음·삭제 실패 구분, 실패 시 내용·목록 유지 | 제3자의 직접 접근은 찾을 수 없음. 수신자만 읽음 변경, 발신자는 읽음 버튼 없음 |
| S-10 | 대상 확인·발송 중 표시 | 대상 없음은 친구 선택 안내 | 수신자·본문 오류 표시, 실패 시 입력 보존 | 친구 관계가 끝났다면 발송 제한 안내. URL의 수신자 값만 신뢰하지 않음 |
| S-11 | 방 목록·대화 시작 처리 표시 | “아직 대화가 없어요”와 친구 목록 링크 | 목록·방 생성 실패 후 재시도 | 자신이 참여한 방만 표시, 과거 친구와의 방은 읽기 전용 상태 안내 |
| S-12 | 이력·이전 이력·전송·복구 중 표시 | 메시지 없음과 입력 안내 | 전송 실패 항목의 재시도, 복구 실패 안내·재조회 | 비참여자 접근 거부. 친구 삭제 후 기존 이력 읽기는 유지하고 전송창을 제한 안내로 전환 |

실패 뒤 재시도는 사용자의 명시적 행동으로 제공한다. 전송 성공을 확인하지 못한 메시지는 성공한 것처럼 지우지 않는다. 같은 채팅 전송의 재시도에는 같은 전송 ID를 사용하고, 응답·이력·실시간 이벤트가 중복 도착해도 한 줄로 보이는 것이 목표다. 정확한 요청·응답·오류 코드는 기능별 API 계약에서 확정한다.

## 5. 댓글·친구·대화의 세부 행동

| 행동 | 화면에서 보일 결과 · WHY |
| --- | --- |
| 댓글 작성·수정 | 글 상세에서 처리하며 성공 후 본문·목록·개수를 API 결과에 맞춰 갱신. 실패하면 사용자가 쓴 내용을 보존 |
| 답글 작성 | 부모 댓글 바로 아래에 대상과 입력창 표시, 취소 가능. 답글에 다시 답글을 다는 버튼은 제공하지 않아 깊이 1단계 정책과 일치 |
| 댓글 삭제 | 삭제 확인 뒤 본문·작성자 대신 삭제 안내를 표시하는 초안. 남은 답글은 부모 자리 아래 유지. 삭제된 부모에 새 답글은 금지 |
| 많은 댓글·답글 | 부모 댓글과 해당 답글의 관계를 유지하며 더 보기 제공. 부모가 화면에서 빠져 답글만 뜨지 않도록 조회·표시 기준을 API 계약에 반영 |
| 친구 요청 | 글 작성자 옆에서 요청 가능·보냄·받음·친구 상태를 구분. 중복·반대 방향 요청은 안내와 현재 상태 갱신으로 처리 |
| 친구 수락·거절 | 받은 요청에서만 행동 제공. 수락 성공 후 받은 요청에서 빠지고 친구 목록에 표시. 이미 처리된 요청의 응답도 안내 |
| 친구 삭제 | 두 사람의 친구 관계가 끝나며 내 목록에서 빠짐. 기존 쪽지·대화 이력은 유지되지만 새 쪽지·채팅 전송은 제한된다는 영향까지 확인창에 표시 |
| 다시 친구가 된 뒤 채팅 | 새 방을 중복 생성하지 않고 기존 방을 열며 전송을 다시 허용하는 안 |
| 채팅 수신·화면 이동 | 최신 위치를 보던 사용자는 새 메시지를 따라가고, 과거 이력을 읽던 사용자의 위치는 유지하며 새 메시지 이동 버튼 제공. 방 전환·로그아웃 때 이전 방 구독과 늦은 응답 정리 |

## 6. 기본 시각 방향과 입력·삭제 확인

밝은 배경, 읽기 쉬운 어두운 본문, 한 가지 강조색, 시스템 글꼴, 목록 중심의 차분한 구성을 제안한다. 정확한 색상·간격·구성 요소는 STEP 02 공통 UI 검토에서 결정한다. 글·댓글·쪽지·채팅 본문은 일반 텍스트와 줄바꿈으로 보여 주며 사용자가 쓴 HTML을 실행하지 않는다.

| 항목 | 제안 동작 · WHY |
| --- | --- |
| 입력 오류 | 필드 라벨·입력 기준·해당 필드 아래 오류를 연결하고 첫 오류로 초점 이동. 색만으로 오류를 구분하지 않음 |
| 저장 오류 | 폼 위에 실패 이유와 재시도 안내, 입력 값 유지. 성공을 받기 전 폼 초기화·화면 이동을 하지 않음 |
| 처리 중 | 버튼에 등록 중/수락 중/발송 중 표시, 동일 행동의 반복 클릭 방지. 서버의 중복 처리 검증은 별도로 필요 |
| 글 삭제 확인 | 대상 제목과 댓글도 함께 삭제되는 영향을 표시. 취소·삭제 두 행동, 기본 초점은 취소. 성공 후 목록 이동 |
| 댓글 삭제 확인 | 본문 삭제와 답글 보존, 복구할 수 없다는 초안 정책 표시. 성공 후 해당 자리 갱신 |
| 친구 삭제 확인 | 상대 이름, 기존 기록 유지와 신규 발송 제한의 영향 표시. 실패하면 기존 관계 표시 유지 |
| 쪽지 삭제 확인 | “내 쪽지함에서 삭제하며 상대의 기록은 유지됩니다” 표시. 성공 후 내 함으로 이동 |
| 확인창 접근성 | 키보드로 열기·취소·확인 가능, 초점이 창 안에서 이동하고 닫으면 원래 버튼으로 복귀. 삭제 후 버튼이 없어졌으면 가까운 안정된 위치로 이동 |

## 7. 데스크톱·모바일 스케치

아래는 흐름을 검토하기 위한 텍스트 스케치다. 구현 화면이나 디자인 확정안이 아니다.

```text
데스크톱 · 글 상세
┌ community-lab │ 게시글 친구 쪽지 채팅 │ 사용자·로그아웃 ┐
│ 목록으로                                              │
│ 글 제목                                               │
│ 작성자 이름 [친구 요청]             [수정] [삭제]       │
│ 본문                                                  │
│ 댓글 ─────────────────────────────────────────────── │
│ 부모 댓글       [답글] [작성자에게만 수정·삭제]         │
│   └ 답글        [작성자에게만 수정·삭제]                │
│ 댓글 입력 · 필드 오류                                  │
│                                            [등록]     │
└───────────────────────────────────────────────────────┘
```

수정·삭제는 로그인한 작성자에게만 보인다. 본문 너비를 제한하고 긴 제목·주소·댓글은 줄바꿈해 가로 넘침을 피한다. 답글 들여쓰기는 좁은 화면에서도 본문을 읽을 공간이 남도록 작게 둔다.

```text
모바일 · 대화 화면
┌ [채팅 목록] 상대 이름 [메뉴] ┐
│ 연결 상태 · 읽기 전용 안내   │
│       [이전 메시지]           │
│ 상대 메시지                  │
│                  내 메시지   │
│          전송 실패 [재시도]   │
│       [새 메시지로 이동]      │
│ 메시지 입력                  │
│                       [전송] │
└──────────────────────────────┘
```

모바일은 메뉴를 접고 본문을 한 열로 배치한다. 채팅 목록과 대화는 각각 한 화면을 사용한다. 키보드가 열려도 입력창·전송 버튼·실패 안내가 가려지지 않아야 하며, 고정 요소가 이력을 덮지 않아야 한다. 데스크톱에서는 공간이 충분할 때 방 목록과 대화를 나란히 보여 주는 배치를 검토한다.
